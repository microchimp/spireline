## Blockers in the lab's tools, independent of the count

1. **The second candidate would be judged on attempt 1's refused block.** A candidate's identity in `promotions.tsv` is its combat
   prior's sha (`describe()["prior_sha256"]`), and attempt 2 keeps generation 11's prior, so its sha is `64d057e174ac`, the same
   as attempt 1's. Checked read-only with the lab's own functions against the real `promotions.tsv`:
   `block_used_by_another("E12-2026-11-02", sha)` is False, so `resolve_e_block` returns the refused block, not a fresh one;
   `attempts_before` gives 0, so the row would read "attempt 1/2" and the guard's cap (`attempts_spent`) stays None. D47 and D51
   want a fresh-seed block, and a fit with beta chosen after seeing E12 should not be tested on E12. Needs a fork change (the
   identity includes the V_run fit's sha, or the block rule counts the fit) with a test; not made today (no fork code changes).
2. **`build` cannot place attempt 2.** `build_candidate` writes only `gen12/candidate`, which exists and holds attempt 1 with its
   `promotion.json` (it refuses a non-empty directory); `build --marker-dir` refuses because `LAB/train/done-11-g12` exists; a
   hand-written `ready-11-g12` would make `train` print "nothing trained or judged" and consume it, because `built_candidate`
   finds attempt 1's judged directory. There is no `candidate-r1` form for built candidates (the `-r<n>` marker means a retrain
   of a trained one). Options: a `build --retrain` form (code), or the orchestrator moves attempt 1's folder and marker aside
   (then fix 1 still applies).
3. **Beta is not tuned.** D47 says "beta tuned"; `vrun-fit` defaults to beta 0 and no tuning has been done or specified. Each
