# Lane 6a: let code keep the books (the lab runner, markers, the weekly real block)

Written 2026-11-19 by lane 6a (Sonnet). Branch `feat/lab-books` in the fork, worktree `wt-lab-books`. Python only; no game, no emulator.

Words once: a **core-hour** is one of the PC's 16 processor threads busy for an hour. The **keep rule** is the fixed test that decides whether a candidate player is promoted (v1, v2, v3 by version). A **marker** is a small file in `LAB/train/` that tells the lab's judging job "this candidate is ready". A **clock block** is the real-game check that starts because a week has passed; a **promotion block** starts because someone wrote `LAB/nightly/pending`. **QUIET.lock** is the shared file where a heavy job says "leave the machine to me".

## What changed

1. **`tools/lab/labrun.py`, a wrapper for heavy work started by hand.** `python tools/lab/labrun.py --tag T --purpose "why" --consumer "who reads it" [--quiet] [--cores N] -- command...` runs the command at BelowNormal priority inside a Windows Job Object (so every process it starts is counted and ends with it) and appends one line to `LAB/hand-jobs.jsonl`: start, end, wall seconds, CPU seconds of the whole tree, cores used, exit code, tag, purpose, consumer. `--quiet` holds its own QUIET.lock line (Windows pid, refreshed every 15 minutes, removed however the command ends) and refuses at once (exit 75) when another holder's line under two hours old stands, the fight loop's `gym-loop` apart. It also refuses to start during a nightly real-game block (`--allow-night` overrides; not for a task). `--report [--since DATE]` prints core-hours by tag, by purpose and by consumer from `LAB/runner.log` and the hand jobs together, with the failed runs' share and how much of the PC's thread-hours the two logs account for.
2. **Markers carry the keep rule.** A marker may have a second line `keep_rule: v3` (`gen0.py build` and `build-vrun` write it with `--keep-rule`). The judging job (`gen0.py train --marker-dir`) uses the newer of the marker's rule and the one `LAB/jobs.json`'s train command names *when the judgement starts*, prints both, and records which it used and why: `promotion.json` `keep_rule_choice`, the ledger's `rule` column (the rule that judged) and the end of the row's `guard` cell. A marker without the field gets the lab's rule and a log line saying so; a marker naming a rule that does not exist stops the round (the marker stays). The generation-18 race (marker two minutes ahead of the switch to v3) now judges under v3.
3. **The real block by the calendar** (`rl/nightly_real.py`). A clock block plays the incumbent alone, at 2,000 runs when any generation was promoted since the last block and at `--runs` otherwise. A promotion block plays at most the incumbent (when it was promoted since; idle otherwise). `--all-promoted` brings the old behaviour back. The result file and the log name the generations left out. A `--since` older than the last block is read as the last block's start, so one left in the job's command cannot turn every later block into a 2,000-run promotion block. On the live agent folder, with the last block's date of 2026-11-06, the old code would have played five players (g14 to g18, 10,000 real runs, about 38 hours); the new code plays g18 only. Tonight's block is unchanged: g18 at 2,000.
4. **Alerts for the silent failure kinds** (`tools/lab/alerts.py`, `runner.py`). Already there: two failures in a row hold a kind and write `<kind>.txt`; every time-limit kill is listed in `timeouts.txt`. Added, each one file under `LAB/alerts/` and one log line, nothing held: `<kind>-repeat.txt` (more than two failures in 24 hours, successes in between or not), `<kind>-timeout.txt` (two time-limit kills in seven days), `quiet-lock-<tag>.txt` (a QUIET.lock line more than an hour old whose process is gone; one per distinct line). Counts live in the runner's `state.json`, so a restart forgets none. Removing a file starts its count again.
